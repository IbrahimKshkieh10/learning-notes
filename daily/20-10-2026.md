## Revision: searching and time complexity

**Linear search** goes through the elements one by one, from the start (or the end), until it finds the one we want. In the worst case we are unlucky and it is the last element, so it takes n steps. Worst case: O(n). Best case: Ω(1), when the first element is the one we want.

**Binary search** uses divide and conquer, and it requires the data to be sorted. The reason is that it works by comparison: if the data is not sorted, a comparison tells us nothing about which side to go to, and we get wrong results.
1. Go to the middle element and compare it with the value we want.
2. If equal, we are done.
3. If the value we want is smaller, repeat on the left half. If it is larger, repeat on the right half.

Each step throws away half of the remaining data, so the worst case is O(log n). The best case is Ω(1), when the middle element is the one we want.

**Time complexity** measures how fast an algorithm is as the input grows, so we can compare one algorithm with another. From fastest to slowest:
- O(1): constant
- O(log n): binary search
- O(n): linear search
- O(n log n): efficient sorting
- O(n²): nested loops over the data

**Notation**
- O (big O) is the upper bound, the worst case.
- Ω (omega) is the lower bound, the best case.
- Θ (theta) is used when the best and worst case are the same. Binary search has no single Θ, because its best case (1) and worst case (log n) differ.
- Asymptotic notation describes how an algorithm behaves as the input gets larger and larger.
